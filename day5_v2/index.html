0. Our question and setup

Together · 10 minutes. On Day 4 you predicted litter mass loss from the number of global change factors. Today we use the identity of each factor, recorded in twelve 0/1 columns. Both models use exactly the same response and predictors.

Role Today’s choice
Response Decom: proportional tea litter dry mass loss during incubation
Predictors Twelve columns indicating factor absence (0) or presence (1)
First model CART: classification and regression trees, used here for regression
Second model Random forest regression, with 25 trees and 50 importance permutations

Decom = 0.65 means 65% of the initial litter mass was lost. This course uses it as the decomposition response. Keep it numeric: a numeric response makes this a regression task even though the predictors are binary.

By the end, you should be able to: select the 0/1 predictor matrix; build and plot a regression tree; describe conditional factor patterns along complete paths; fit the guided random forest model; and interpret a permutation-importance ranking.

Keep each experimental unit once

The soil dataset contains the single-factor observations twice: once under named factor labels and once under remark = "1". Select the summary labels below to keep one copy of those observations, together with controls and multi-factor observations. Do this before splitting the data.

soil_raw <- read.csv("MultiFactor_data.csv")
factor_names <- c("P", "C", "L", "N", "A", "I", "SU", "FU", "H", "M", "S", "D")
soil_once <- soil_raw[soil_raw$remark %in% c("CT", "1", "2", "5", "8"), ]

nrow(soil_raw)
nrow(soil_once)
head(soil_once[, c("Decom", factor_names)])
table(as.matrix(soil_once[, factor_names]), useNA = "ifany")
all(rowSums(soil_once[, factor_names]) == soil_once$Lv)

keep <- complete.cases(soil_once[, c("Decom", factor_names)])
excluded_ids <- soil_once$X[!keep]
excluded_ids
model_data <- soil_once[keep, c("Decom", factor_names)]
rownames(model_data) <- paste0("record_", soil_once$X[keep])

We remove rows missing the response or a selected predictor.

Split dataset into training and test sets

The training dataset lets the model learn splits and prediction rules. The test dataset checks how well those rules predict observations that were not used to build or choose the model.

Discuss with your partner: A tree predicts the observations used to train it very accurately. Does this show that it will predict new soil samples accurately? What evidence would you want before trusting it?

Check: learning versus evaluating

If we train on all observations and assess the model on those same observations, the evaluation reuses information the model has already seen. A flexible tree can fit accidental patterns as well as the ecological signal: this is overfitting. Its training error may be small while its error on new observations is larger.

For the first CART illustration only, use a fixed random split: split 75% data into training set, 25% data into test set. This results in 189 training observations and 63 test observations.

set.seed(505)
train_rows <- sample(seq_len(nrow(model_data)), size = floor(0.75 * nrow(model_data)))
train_data <- model_data[train_rows, ]
test_data <- model_data[-train_rows, ]
nrow(train_data)
nrow(test_data)

set.seed() makes the random choice repeatable with the same R setup. The minus sign selects rows outside train_rows.

This split holds out individual microcosms. It assesses prediction for other units from the training set; it does not specifically test prediction for entirely unseen combinations, sites or experiments.

2. Build and visualise a CART regression tree

A regression tree repeatedly separates observations into groups with more similar response values. Each final group, or leaf, predicts its training mean. The fitted tree can represent different patterns in different factor backgrounds.

Because train_data contains only the response and twelve indicators, Decom ~ . means “predict Decom using all other columns.” The dot would be unsafe if unrelated columns were still present.

tree_model <- rpart(
  Decom ~ .,
  data = train_data,
  method = "anova",
  control = rpart.control(maxdepth = 3, minbucket = 10, cp = 0.01, xval = 0)
)
print(tree_model)

method = "anova" selects squared-error regression splitting; this is not the group-comparison ANOVA exercise from Day 4. We pre-set a maximum depth of three and at least ten training observations per leaf to keep the diagram manageable. cp limits small improvements. Internal cross-validation is off (xval = 0) for this first illustration; Step 3 introduces CV using the full prepared dataset.

rpart.plot(tree_model, type = 2, extra = 1, yesno = 2, fallen.leaves = TRUE,
           digits = 3, roundint = FALSE, box.palette = "GnBu",
           main = "CART: predicted litter mass loss")

Enlarge the RStudio Plots pane or select Zoom. The diagram shows a fitted mean and an observation count in each node. Read the written condition and its yes/no branch labels. With numeric 0/1 predictors, a boundary of 0.5 separates absence from presence; it is not an ecological dose threshold.

Your task: identify the first split, count the leaves, and find the leaf with the lowest predicted decomposition. Which factor conditions lead there?

Check: reference tree

With the supplied data and seed, salinity (S) is the first split and the tree has five leaves. Its lowest predicted mass loss is about 0.558, or 55.8%, for salinity present and drought present. Follow the displayed conditions: the location of a branch on the page alone does not tell you whether a factor is present.

Check predictions on the test set

Use the 63 observations test set aside earlier to calculate prediction error for this first tree. Multiplying the root mean squared error (RMSE) by 100 expresses it in percentage points of litter mass loss.

first_cart_pred <- predict(tree_model, newdata = test_data[, factor_names])
first_cart_rmse <- sqrt(mean((test_data$Decom - first_cart_pred)^2))
100 * first_cart_rmse

The reference RMSE is about 3.62%.

3. Repeat CART with cross-validation

A short explanation: cross-validation

k-fold cross-validation (CV) divides the full prepared dataset into k groups, called folds. Fit a model using k-1 folds and predict the remaining fold; repeat until each fold has been left out once. Every observation is used for fitting in k-1 rounds and for validation in one round.

Task A · Switch on five-fold cross-validation

Assign every observation to one of five folds. Passing these fold IDs to xval requests five-fold CV.

set.seed(505)
cv_folds <- sample(rep(1:5, length.out = nrow(model_data)))
table(cv_folds)
tree_cv <- rpart(
  Decom ~ .,
  data = model_data,
  method = "anova",
  control = rpart.control(maxdepth = 3, minbucket = 10, cp = 0.01, xval = cv_folds)
)
printcp(tree_cv)
print(tree_cv)

Read the complexity-parameter table before choosing a size:

Column How to read it
CP Complexity parameter defining a candidate pruned tree
nsplit Number of splits; a tree has one more leaf than splits
rel error Relative training error
xerror Relative cross-validation error; smaller is better
xstd Estimated standard error of the CV error; not a p-value

Discuss: Does the row with the smallest training error also have the smallest CV error? Why might keeping an extra split reduce training error without improving predictions for held-out observations? xerror is on a relative error scale, not an RMSE scale.

Task B · Select and plot the pruned tree

For this exercise, select the row with the smallest xerror, extract its CP, and prune the fitted tree. which.min() returns the position of the smallest value.

best_row <- which.min(tree_cv$cptable[, "xerror"])
best_cp <- tree_cv$cptable[best_row, "CP"]
best_cp
tree_cv_pruned <- prune(tree_cv, cp = best_cp)
print(tree_cv_pruned)

rpart.plot(tree_cv_pruned, type = 2, extra = 1, yesno = 2, fallen.leaves = TRUE,
           digits = 3, roundint = FALSE, box.palette = "GnBu",
           main = "CART: tree size selected by five-fold CV")

This pruned tree uses all 252 observations for its final leaf means. CV was used to choose its size. tree_model remains the first illustration; from now on, interpret and save tree_cv_pruned as the CART model.

Keep the predictions made when each observation was in a held-out fold. xpred.rpart() returns one column for each candidate size; best_row selects the size chosen above.

cart_cv_pred <- xpred.rpart(tree_cv, xval = cv_folds)[, best_row]

4. Guided practice: fit a small random forest

One tree gives readable paths but can change substantially when the fitting sample changes. A random forest averages predictions from multiple trees, using resampled observations and random subsets of predictors at each split. Fit this forest using all 252 observations in model_data and the same twelve predictors.

Task A · Complete the two settings

Copy the template, replace the blanks, and explain each setting to your partner. Use 25 trees and 50 permutations for less heavy computation. Do not run the template with blanks.

set.seed(505)
rf_model <- randomForest(
  x = model_data[, factor_names],
  y = model_data$Decom,
  ntree = ___,
  mtry = 4,
  nodesize = 5,
  importance = TRUE,
  nPerm = ___
)
  • x is the twelve-column 0/1 predictor matrix; y is the numeric decomposition response.
  • ntree controls the number of trees. Keep it at 25 or fewer in this practical.
  • mtry = 4 makes four randomly selected predictors available at each split. The model still receives all twelve factors.
  • nodesize = 5 limits how small terminal groups can become during tree growing.
  • importance = TRUE requests importance calculations.
  • nPerm = 50 repeats predictor shuffling on out-of-bag observations for importance within each tree. It does not mean 50 forest refits or a significance test.
Check and run: completed random forest 
set.seed(505)
rf_model <- randomForest(
  x = model_data[, factor_names],
  y = model_data$Decom,
  ntree = 25,
  mtry = 4,
  nodesize = 5,
  importance = TRUE,
  nPerm = 50
)
print(rf_model)

The printed model should say regression, 25 trees, and 4 variables tried at each split. It uses all 252 observations. The response must stay numeric.

Task B · What does out-of-bag mean?

For each tree, some observations are omitted from its bootstrap sample. Those are that tree’s out-of-bag (OOB) observations.

rf_oob_rmse <- sqrt(tail(rf_model$mse, 1))
100 * rf_oob_rmse

Explain: Why would evaluating only on the observations used to build a tree make its predictions look too good?

Check: error and computation

A tree has already used its fitting responses to choose splits, so training error can be optimistic. OOB observations provide an internal check. The reference forest OOB RMSE is about 3.77 percentage points. With only 25 trees, predictions, OOB error and rankings can vary. Fifty importance shuffles do not compensate for a small forest. This is a lightweight classroom model, and a forest is not guaranteed to outperform CART.

5. Sort the factors by permutation importance

If shuffling a factor’s 0/1 values makes OOB prediction worse, that means the model used information from that factor. A larger increase in error means greater predictive importance in this fitted forest.

Extract the unscaled permutation measure, then put it into a table:

perm_importance <- importance(rf_model, type = 1, scale = FALSE)
importance_table <- data.frame(
  factor = rownames(perm_importance),
  delta_mse = as.numeric(perm_importance[, 1]),
  row.names = NULL
)

type = 1 selects permutation importance. scale = FALSE retains the change in mean squared error (MSE), measured in squared mass-loss proportions. We call the column delta_mse to describe this scale. It is not a percent increase, despite the package’s default column label, and it is not a p-value.

Your turn · Sort largest first

Write a command to sort the table from the highest to the lowest delta_mse. Hint: order(-importance_table$delta_mse) gives row positions in descending order. Use those positions before the comma in importance_table[rows, ].

Check: descending importance table 
importance_table <- importance_table[order(-importance_table$delta_mse), ]
print(importance_table, row.names = FALSE)

For the supplied seed and software, salinity (S) and drought (D) rank first and second; lithium (L) ranks third in this full-data forest. Close or low ranks can change. Compare your actual output before copying a conclusion.

Visualise all twelve ranks

This plot reverses the sorted rows so that the highest importance appears at the top. A zero line helps identify factors whose importance is near zero or negative.

par(mar = c(5, 5, 3, 1))
barplot(rev(importance_table$delta_mse),
        names.arg = rev(importance_table$factor),
        horiz = TRUE, las = 1, col = "#39745b", border = NA,
        xlab = "Increase in OOB MSE (proportion squared)",
        main = "Random forest: permutation importance")
abline(v = 0, col = "grey40", lty = 2)
Check: reference ranking plot

Write three short answers:

  1. Name the top three factors, using full ecological names as well as their codes.
  2. Does high positive importance tell you that a factor increases decomposition?
Check: what importance can tell us

High importance indicates a contribution to prediction, not an effect direction or effect size. A factor can be important because it predicts lower values, higher values or different patterns in different backgrounds. Read the tree for specific conditional predictions.

Use sessionInfo() to record your software when troubleshooting.

What is intentionally kept small?

The full-data forest uses 25 trees, 50 OOB importance permutations and one fixed mtry. CART candidates stay shallow. There is no grid search, response-permutation significance test or nested cross-validation. Formal interaction testing and validation for new combinations are separate analyses. Students who finish early can discuss how they would hold out whole combinations, without running another model.
